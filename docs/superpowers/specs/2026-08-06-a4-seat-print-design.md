# A4 座位表列印功能設計

## 目標

在既有員旅座位網站加入兩份可列印的 A4 橫式座位表：棒球賽一頁、餐廳一頁。列印頁每次開啟都讀取最新 API 資料，可直接送印表機或由瀏覽器另存成 PDF。

## 採用方案

使用瀏覽器原生列印功能與專用列印頁，不新增 PDF 或伺服器產檔套件。這可沿用瀏覽器成熟的中文字型排版，避免部署環境缺字型時姓名變成方塊，也不增加 Railway 的執行負擔。

不採用前端 PDF 套件，因為需要額外嵌入大型中文字型；不採用後端 PDF 服務，因為需要在 Railway 安裝並維護字型與產檔工具。

## 使用流程

1. 棒球賽首頁提供「列印 A4 座位表」連結，開啟 `/print/baseball`。
2. 餐廳頁提供相同連結，開啟 `/print/lunch`。
3. 專用頁面以 `cache: "no-store"` 重新讀取對應 API。
4. 載入完成後顯示最新座位表、已安排人數與 Asia/Taipei 產生時間。
5. 使用者按「列印／另存 PDF」呼叫瀏覽器列印視窗。
6. `@media print` 隱藏操作列，只輸出一張 A4 橫式頁面。

## 棒球賽版面

- 標題為「0807 員工旅遊｜新莊棒球場座位表」。
- B1 與 B2 依既有座位定義分區，按照排數與座號由小到大排列。
- 每個座位格顯示座號、姓名、部門／備註。
- 空位保留座位格並顯示「空」。
- 頁尾顯示已安排席次與總席次 71。

## 餐廳版面

- 標題為「0807 員工旅遊｜饗 A JOY 午餐座位表」。
- 依既有 `lunchZones` 的 R／B 區、群組與桌號順序排列，不另建第二份桌位資料。
- 45 張桌卡以三欄呈現；每張卡顯示桌號、容量，以及全部座號。
- 每個座位顯示座號、姓名、部門／備註；空位顯示「空」。
- R05、R06、R07 使用目前正式定義的 4 人容量，全場總席次 191。

## 元件與資料邊界

- `lib/print-layout.ts`：提供棒球座位定義、排序與列印資料轉換的純函式，供頁面與測試共用。
- `app/print/print-client.tsx`：負責讀取 API、載入／錯誤狀態、台北時間及列印操作。
- `app/print/baseball/page.tsx`：棒球賽 A4 版面。
- `app/print/lunch/page.tsx`：餐廳 A4 版面。
- `app/print/print.css`：只服務列印頁，固定 A4 橫式、頁邊距、字級與防溢位規則。
- 現有兩個選位頁只新增列印入口，不改寫選位與資料寫入邏輯。

## 錯誤處理

- API 載入期間顯示「正在讀取最新座位資料」。
- API 回傳錯誤或網路失敗時顯示明確訊息與「重新載入」按鈕。
- 尚未成功取得資料前，不顯示列印按鈕，避免印出空白或過期內容。
- API 中存在餐桌容量調整後的孤兒資料時，在餐廳列印頁顯示警告清單，提醒現場重新安排。

## 測試與驗收

- 純函式測試覆蓋棒球 71 席、B1／B2 座位範圍、餐廳 191 席與空位保留。
- ESLint 與 Next.js production build 必須通過。
- 使用列印媒體模擬產生兩份 PDF，各自確認只有 1 頁。
- 將兩份 PDF 渲染成 PNG，人工檢查中文字、姓名、課別、空位、欄位對齊與邊界皆未被裁切。

## 不在本次範圍

- 不修改任何線上座位或姓名資料。
- 不加入密碼、登入或新的資料庫表。
- 不產生合併成兩頁的單一 PDF；兩個活動維持各自一份。
- 不自動下載檔案，使用瀏覽器列印視窗選擇印表機或「另存為 PDF」。
