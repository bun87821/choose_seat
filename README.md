# 員工旅遊自助選位

兩個獨立分頁，共用同一個網站與資料庫：

| 路徑 | 用途 |
| --- | --- |
| `/` | 新莊棒球場 B1、B2 區共 71 席劃位 |
| `/lunch` | 0807 午餐（饗 A JOY）194 位座位選位＋停車折抵車號登記 |
| `/lunch/import` | 批次匯入名單，依課別自動排位 |

兩頁最上方都有分頁切換列，可互相跳轉。

## 棒球賽劃位（`/`）

- B1：12–14 排 4–12 號；15 排 5–12 號；16 排 5–14 號，共 45 席
- B2：14 排 7–12 號；15–16 排 5–14 號，共 26 席
- 可一次選擇多席，支援攜伴
- 確認前提醒座位數須與報名人數相符
- 座位即時同步並防止重複劃位
- **換位模式（點一換一）**：選位區上方可切換。點一個已經有人的座位把他「拿起來」，再點另一個座位——點空位是搬過去，點別人就是兩人互換，姓名與備註跟著走，B1、B2 兩區之間也可以互換。互換在單一交易內完成，來源被取消或目標被搶走都會整批回滾。關掉就回到原本「點一下取消」的行為
- 所有人皆可逐席取消座位後重新選位
- 公開座位名單與 CSV 下載
- PostgreSQL 永久保存資料

## 午餐座位（`/lunch`）

依 `0807午餐 鄭婉芃(台積電)194位座位圖` 建立，邏輯與棒球賽劃位相同。

- B 區 20 桌共 86 位、R 區 25 桌共 108 位，合計 45 桌 194 位。分頁順序與座位圖一致：B 區在餐廳左側（市府路）擺左邊，R 區在右側擺右邊
- **座位卡片**（預設）：卡片維持一般選位介面（桌號、剩餘人數、位子按鈕直接顯示），但擺放位置依照座位圖的相對關係——R 區排成 3 排 × 8 桌、R10 落在最右下，B 區則重現左側三欄與右上角的大圓桌斜向群。空格就是平面圖上的走道，位置一看就對得起來
- **平面圖總覽**：45 張桌子依實際座標縮成一張平面圖，圓桌畫圓、方桌畫方、大小依人數縮放，桌上小圓點代表位子狀態（灰＝已有人、橘＝本次已選）。點一張桌子就在下方展開該桌位子
- 兩種模式都可以跨桌連續選位，最後一次送出
- **找位子**：選位區上方有搜尋框，輸入姓名或課別即時列出符合的人與桌號座號。相符的位子在座位卡片與平面圖上都會亮起金框；點搜尋結果會自動切到對方所在的區、捲到那個位子並多加一圈強調。眷屬（王小明 眷1）與課別關鍵字都找得到
- **換位模式（點一換一）**：選位區上方可以切換。開啟後點一個已經有人的位子把他「拿起來」，再點另一個位子——點空位是搬過去，點別人就是兩人互換，姓名與備註跟著走。互換在單一交易內完成，來源被取消或目標被搶走都會整批回滾。關掉就回到多選模式
- **名單依部門／備註篩選**：座位名單上方有各部門的膠囊按鈕（含人數），點一下就只看該部門，再點一次取消。表頭全選只會勾到目前顯示的那幾筆，CSV 也只匯出篩選後的名單（檔名會帶部門名）。沒填備註的歸在「（未填）」
- **多選取消**：點已有人的位子會把那個人選起來（藍框），可以連點多個再一次取消；座位名單也能用左邊的勾選框複選，或用表頭全選後一次取消
- **整批換桌／整桌對調**：每張有人的桌子上有「選整桌」按鈕，一鍵選起該桌所有人，再從下拉選單挑目標。下拉分成兩組：
  - *搬到空位*：空位足夠的桌子（會把選取中的位子先扣掉再算空位）
  - *與整桌對調*：目標桌已經有人時，兩桌的人整批互換位置。只列出兩邊都坐得下對方的桌子，選取的必須剛好是某一桌的全部人
  - 姓名與備註跟著走，整個動作在單一交易內完成，人數超過對方桌的容量或有人剛好被取消都會整批回滾
- 每桌顯示桌號與可安排人數（座位圖上的米字號數字），桌內位子逐一點選
- 可展開餐廳平面圖（`public/lunch-floorplan.jpg`）對照桌號位置
- **嬰兒座椅**：所有圓桌，加上 R 區中間的 R17、R27、R13、R23 共 22 桌可放嬰兒座椅，桌號旁以 🍼 標記，選位區上方也有說明，座位 CSV 另有「可放嬰兒座椅」欄位
- **參加人數**：選位前先選參加人數（含本人），攜眷就選 2 以上。選的位子數必須與參加人數一致才能送出，眷屬座位會自動標成「王小明 眷1」
- 一樣可一次選多個位子、即時同步、任何人都能取消後重選
- **停車折抵車號登記**：填姓名＋車號即可登記，名單公開並可下載 CSV 提供給餐廳折抵停車費。車號存檔時一律轉大寫並去掉連字號與空白，所以 `ABC-1234`、`abc 1234`、`ABC1234` 會被視為同一台車擋下重複登記；顯示與 CSV 則自動補回連字號
- **留言板**：頁面最下方的公開聊天區，填暱稱＋內容即可留言（單則上限 300 字，`Ctrl`／`⌘ + Enter` 送出）。每 5 秒自動更新，最多顯示最近 200 則，任何人都可以刪除任一則。暱稱留空會沿用上方填的姓名
- 桌位資料集中在 `lib/lunch-tables.ts`，前端與 API 共用同一份定義

## 本機執行

需求：Node.js 22+、PostgreSQL。

```bash
cp .env.example .env.local
npm install
npm run dev
```

把 `.env.local` 裡的 `DATABASE_URL` 改成自己的 PostgreSQL 連線字串。資料表會在第一次請求時自動建立，不需手動執行 migration。

## 批次匯入名單（`/lunch/import`）

先用主辦手上的名單把大家排好座位，再開放大家自己換位。

1. **貼上名單**：每行一位同仁、格式為「姓名　課別　參加人數」，直接從 Excel 複製三欄貼過來即可（Tab 分隔）；也接受逗號、頓號、分號分隔。第一行若是標題會自動略過。畫面即時顯示讀到幾位同仁、總人數與眷屬人數，以及各課別幾人。
   - **參加人數含本人**，攜眷就填 2 以上，省略或不是數字時當作 1 人。
   - 同一位同仁與他的眷屬算「一組」，排位時**不會被拆到不同桌**（除非該組人數超過最大的 8 人桌，或全場已經快坐滿；這種情況預覽會列出是哪幾組）。
   - 眷屬的座位會標成「王小明 眷1」「王小明 眷2」，名單與 CSV 一看就知道誰是攜眷。
2. **排位規則**：
   - *同課別盡量坐同一桌*：替每個課別找一段**在座位圖上連續**的桌子，先求用到的桌數最少、再求浪費的空位最少。一個課別不會被排到場地的兩側——R 區、B 區與獨立的 R10 各自成區，區塊不跨區（只有全場快坐滿、湊不出整段時才會退回「有位就填」）。
   - **推進方向是由右往左、一個直行一個直行**（同一行由上往下），不是照桌號大小。照桌號排的話，第一個也是人最多的課別會沿著最上面那排一路吃過去，把整排靠牆的好位子佔光；改成走直行之後，每個課別拿到的是縱向的一小塊，最上排的桌子自然分給不同課別。實測 12 課別 180 人：舊順序最上排 8 桌被同一課佔走 5 桌，新順序單一課別最多只佔 2 桌、由 5 個課別分享，而且每課別平均用的桌數沒有變多（都是 3.5 桌）。
   - *人多的課別先挑桌*：總人數多的課別優先拿大桌，比較不會被拆散。桌內則是大組先坐，避免卡在零星空位。
   - 兩個都關掉就照名單順序從頭依序填。
3. **預覽並手動微調**：以桌為單位列出每個位子。
   - 點一個人把他「拿起來」，再點另一個位子就搬過去；點到別人身上就兩人互換。
   - 每個人右邊的 ✕ 會把他移到上方的「待安排」區；點待安排區的人再點一個空位就放回去。排不下的人也會出現在這一區。
   - 勾「顯示全部 45 桌」可以把人搬到還沒排到人的桌子。
   - 已經有人的位子會顯示 🔒 而且不能點，怎麼調都不會動到。
4. **寫入**：只會填**目前的空位**，所以可以分批匯入。課別會寫進備註欄，名單與 CSV 都看得到。

### 已經有人的位子不會被動到

- 匯入頁每 5 秒同步一次座位，預覽永遠排在當下的空位上。
- 按下寫入時會再抓一次最新狀態；如果預覽期間有位子被選走，**不會寫入任何資料**，而是把受影響的人自動改排到其他空位，請你重新確認預覽。
- API 端在同一個交易裡先鎖定並檢查目標位子，只要有一個已經有人就整批回滾並回報是哪幾個；資料表主鍵是最後一道防線。寫入一律是 `INSERT`，沒有任何會覆蓋既有資料的路徑。
- 換桌也一樣：目標桌的空位是在交易內重新計算的，只會落在真正沒人的位子上。

寫入後大家照樣可以到 `/lunch` 自己換位、整批換桌或取消。要整個重排的話，先在 `/lunch` 用全選取消清空再匯入一次。

## 部署到 Railway

1. 在 GitHub 建立空白 Repository，把本專案推上去。
2. Railway 選擇 **New Project → Deploy from GitHub repo**。
3. 在同一個 Railway Project 新增 **PostgreSQL** service。
4. 到網站 service 的 **Variables**，加入：

   ```text
   DATABASE_URL=${{Postgres.DATABASE_URL}}
   ```

   如果 PostgreSQL service 名稱不是 `Postgres`，請把參照名稱改成實際名稱。
5. 重新部署網站 service。
6. 到 **Settings → Networking → Generate Domain** 取得公開網址。

Railway 會依照 `railway.json` 執行：

```text
npm run build
npm run start
```

## 修改座位需要確認密碼

取消、換位、整批換桌、整桌對調這些**動到既有座位**的操作，都要輸入確認密碼（預設 `870821`）。

- **選新位子不需要密碼**，同仁照樣可以自己劃位；車號登記與留言板也不需要。
- 一個瀏覽階段輸入一次就好，後續操作不會重複詢問（存在 `sessionStorage`，關掉分頁就失效）。密碼錯誤時會清掉重問。
- 驗證在 **API 端**進行，密碼不會出現在前端 JS 裡；沒帶或帶錯密碼一律回 `401` 且不動任何資料。
- 要改密碼的話，在 Railway 的 **Variables** 加上 `SEAT_EDIT_PASSWORD`，不必改程式。

> 這是「防手滑、防路人亂改」的確認機制，不是嚴謹的權限系統——預設值寫在程式碼裡，知道密碼的人都能修改任何座位。

## 重要說明

- 原本 ChatGPT Sites 網站的劃位資料不會自動移轉到 Railway。
- 網站會公開姓名、座位、備註與留言，請只把連結提供給預期的使用者。留言板沒有身分驗證，任何人都能發言與刪除。
- 座位不綁定瀏覽器；知道確認密碼的人都可以取消或搬動任一座位。

## 專案結構

```text
app/
  api/reservations/route.ts        # 棒球賽劃位 API
  api/lunch-reservations/route.ts  # 午餐選位 API
  api/parking/route.ts             # 停車折抵車號 API
  api/messages/route.ts            # 留言板 API
  seat-picker.tsx                  # 棒球賽選位介面
  lunch/page.tsx                   # 午餐分頁
  lunch/lunch-picker.tsx           # 午餐選位與車號登記介面
  lunch/import/import-panel.tsx    # 批次匯入名單與排位預覽
  globals.css                      # 樣式
lib/
  db.ts                            # PostgreSQL 連線與資料表初始化
  lunch-tables.ts                  # 午餐桌號、每桌人數、平面圖座標與卡片格線位置
  plate.ts                         # 車號正規化與格式檢查
  seat-assign.ts                   # 名單解析與依課別的自動排位
public/
  lunch-floorplan.jpg              # 午餐座位平面圖
railway.json                       # Railway 建置與啟動設定
```

資料表（第一次請求時自動建立）：`reservations`、`lunch_reservations`、`parking_plates`、`lunch_messages`。
